# Known issues / limitations (1.8.0)
- KI1: Smoke-tested only under Wine; never on real Windows. Task Scheduler paths, event-log history, installer (32-bit NSIS stub), service control are unexercised.
- KI2: Scan scope: no policy Run, Winlogon/AppInit/IFEO/WMI, packaged apps, other users.
- KI3: StartupApproved format handled for 12-byte values only; others stay read-only.
- KI4: Sign-in impact is "Not measured". No boot/session metrics.
- KI5: No tray monitor, scheduled service operations, remote machines, CLI, code signing.
- KI6: UI Automation covered by native buttons/listview only; custom dashboard/settings panel has keyboard but no UIA provider.
- KI7: Custom service accounts/passwords and "restart computer" recovery intentionally unsupported.
- KI8: Cleaner is conservative by design (4 registry areas, fixed drives only); no file-extension/COM/typelib cleaning, no browser history/cookies. Temp deletion is permanent. Windows Update/Delivery Optimization caches not included.
- KI9: Large files / Duplicates (1.7) are compile-checked only; never executed. Recycle Bin move uses SHFileOperation (Windows prompts itself if a file is too large to recycle). Duplicate hashing reads whole files (can be slow on big drives); scans cannot be resumed.
- KI10: 1.8 is compile-checked only (see TEST_REPORT). Windows Update cache cleanup stops wuauserv/bits and restarts them; if a restart fails the message tells you to start them from the Services page. Windows 7 untested.
- KI11: Cleaner does not yet offer clipboard-history cleaning, installer-package cleaning, exclusion lists or scheduled runs.
- KI12: 2.0 UI (navy theme, GDI+ drawing, Care page, banner, sub-tabs) has never been seen running. Layout may need tuning at small window sizes.
- KI13: Auto-update needs the public repo akshsim1991/FeatherSystemUtilities-releases (latest.json + installer) - see releases-repo/. Until it exists the check says no release is published. Installer is unsigned.
- KI14: Leftover detection is evidence-based but conservative; it cannot find leftovers whose names/paths do not match the program. Deleting leftover folders is permanent.
- KI15: 3.0 WebView2 host + all bridge commands are compile-checked only; the page was tested against a mock bridge in Chromium (no console errors), never inside WebView2. WebView2 runtime on Windows 7/8 is Edge 109 (last supported) and must be installed separately; otherwise the classic UI starts. No scheduler, process manager, privacy cleaner or Store apps page in the new UI yet (classic UI has Services/Drivers/History only).
- KI16: The new UI's Services page hides drivers by default and lacks profiles/properties editors of the classic UI (use `--classic`).
- KI17: Driver updates (WUA COM) and WMI driver inventory are compile-checked only. MinGW's wuapi.h lacks IWindowsDriverUpdate, so update entries show Windows Update's title/description rather than model/class. Reboot-required is only known after install.
- KI18: Open file location now verifies an Explorer window appears (title = folder name or full path). If Explorer is configured with an unusual title the check can time out and a second window may open.
- KI19: Not yet in the new UI: scheduler, privacy/browser-data cleaner, file shredder, Store apps, context-menu manager, services profiles/properties editors (use --classic).
- KI20: Quarantine moves use SHFileOperation (works across drives) and are untested on Windows. Restore point creation uses srclient.dll SRSetRestorePointW and is verified by re-reading the restore point list; it needs administrator rights and Windows limits automatic creation to one per 24 h.
- KI21: The launch update prompt needs the public releases repo to exist; until then the check fails silently at startup.
- KI22: Driver update matching relies on IWindowsDriverUpdate properties read through IDispatch; if Windows does not expose a hardware ID the update is shown as "no matching installed device". Driver install runs through Windows Update Agent in the Feather process and can take minutes with no progress detail.
- KI23: Browser clearing deletes files directly (not recoverable). Chromium history clearing removes the History file (also download history). Redaction (user/computer name, profile paths, SIDs; optional path masking) is best-effort text replacement, untested on Windows.
- KI24: Recommendations are rule-based suggestions (data/advice.json), not live web searches: there is no free, reliable public API for "is this safe to disable?", and scraping search engines would be fragile. The online part downloads an updated rule list from the project's release repo (needs akshsim1991/FeatherSystemUtilities-releases to exist; edit and republish advice.json there to improve advice). "Search online…" opens the user's browser per item.
- KI25: Safe Mode behaviour (service start, classic fallback) is implemented from Windows documentation and untested; the exact failure the owner saw in Safe Mode has not been reproduced.
- KI26: Store app listing/removal runs fixed PowerShell commands (package full names are validated against the list); untested on Windows. Boot impact needs read access to Microsoft-Windows-Diagnostics-Performance/Operational (may need administrator rights) and only covers items Windows flagged.
- KI27: The embedded license public key is a DEV placeholder whose private key was discarded; no license can be issued until you run tools/license_keygen.py and rebuild. No feature is license-gated yet.
- KI28: The update fallback points at the claude/new-session-ann5h4 branch of Application_Development until akshsim1991/FeatherSystemUtilities-releases exists.
